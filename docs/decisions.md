## 行为细化

- 将同一物理设备的 USB / Wi-Fi 连接尽可能归为同一个设备，操作必须指向选中设备及明确的传输通道。
- 自动恢复仅尝试已知、已配置或已配对的同一设备无线连接。失败后停止自动循环，等待用户操作。
- 所有开始操作明确传入 scrcpy 设备标识，避免直接启动时出现“多个 ADB 设备”歧义。
- 启动外部程序使用参数数组，不将设备地址、配对码或路径拼接为 shell 命令。
- 投屏会话和应用状态以真实执行结果更新；浏览器设计预览中的演示数据不得作为真实连接结果。
- “最高”对应 `maxFps: null`，不传 `--max-fps`；手动值按整数校验并原样作为上限。所有启动固定 `--max-size 0`，码率在后端固定为 `8M`，不提供设置项。
- 从 0.1.0 读取配置时忽略旧 `preset`，新帧率默认为“最高”，保留声音、置顶、连接偏好、上次设备和已保存无线地址。

## 旧版差异

0.1.0 曾提供“流畅 / 均衡 / 清晰”预设，并使用较大的主页窗口。0.2.0 已取消这些预设，将可调整项收进设置页。旧版真机记录保留在验收文档中，不视为新版通过。

## 验收边界

版本记录与文件校验由构建脚本产生。真机连接、无线配对和自动恢复必须使用对应条件的设备验证；没有可用硬件时保留待验证状态，不能用编译通过代替。具体条件见 [验收清单](acceptance.md)。

## 0.3.0 三键栏边界

- 使用应用自有的 Win32 窗口，不获取输入焦点（`NOACTIVATE`），不改 scrcpy 窗口位置、大小及快捷键。
- 普通窗口时贴在投屏窗口底边外侧，跟随移动、缩放、最小化及关闭；仅跟踪本应用拥有的当前投屏窗口。
- 全屏或底部空间不足时收起，鼠标进入可见画面底边 6 DIP 时唤出短暂浮层；离开触发边缘与按键栏 350 毫秒后隐藏。
- 最近任务、返回、主页分别发送固定 Android 按键码 `187 / 4 / 3`；只向当前 `Running` 会话的 token 与 serial 发送。
- 停止、恢复连接期间及旧 token 请求一律拒绝，不能转发给新会话或其他设备；失败沿用现有日志反馈。
- 后端隔离测试通过不等于原生窗口、鼠标交互或真机通过；对应验证结果单独记录。

## 0.3.1 延迟与绘制修复

- 三键栏复用已运行 scrcpy 的左 Alt+s/b/h 快捷键通道，不能在每次点击时创建新的 ADB / Android input 进程；Windows 使用 SYSKEY 消息，避免普通 WM_CHAR 混入输入。
- 单纯移动只调整底栏坐标；尺寸或 DPI 变化时才重新布局，不重复设置未改变的启用状态。
- 绘制采用缓冲，避免绘制重入被跳过或背景先显示、图形后显示。
- 发送前仍验证当前就绪会话与自有进程，不抢前台或修改全局键鼠状态。
- 当前物理修饰键或目标字母仍按下时拒绝投递；部分消息投递失败只对原窗口尝试补发释放消息，不向替代窗口清理。此清理为尽力行为，不能保证窗口异常时仍全部完成。
- 本地投递耗时与手机画面端到端响应分别记录，不能将前者当作后者的实测结果。

## 0.4.0 后台 USB 通知边界（2026-11-05）

以下保留 0.4.0 初版约束；通知初始化方式在 0.4.1 调整，见下一节。

- 用户确认：仅 USB；后台仅指主面板最小化或隐藏到托盘，普通失焦不算；已有任一 `Starting / Running / Reconnecting` 会话时不提醒、不切换。
- 复用原有约 3 秒一次的 ADB 成功刷新，依据成功检测时的窗口状态判断，不承诺精确捕获物理插入瞬间，不启动额外高频设备轮询。初始成功快照只建立基线，前台已观测的连接不在稍后入托盘时补发。
- 只有设备已授权、身份及本次 USB attachment 可确认时生成提醒。新插入但未授权时不发可执行通知；授权完成后再次成功检测可产生通知。Wi-Fi 上线不参与此功能。
- 使用原生 `ToastGeneric`，显示“检测到 USB 设备”、设备名称和“是否开始投屏？”。“开始投屏”使用已保存设置启动原 USB，成功后保持面板隐藏；正文仅恢复面板，“暂不”关闭通知。启动失败恢复面板并说明原因。
- 每项通知使用一次性随机 token，绑定 device_id、USB serial 和本次 ADB transport_id，5 分钟后过期。点击须重新发现并核对原连接；不能将失效的 USB 请求改投同设备 Wi-Fi、重插后的新 attachment 或其他设备。令牌先领取后启动，失败后重复点击也不能再次使用。
- 拔出、重插、授权丢失、身份改变、开始其他投屏、面板恢复到非最小化可见状态及退出时撤销待处理操作。迟到或重复的回调不能越过会话、前后台和退出检查。
- 仅当前运行中的进程接收通知操作，不注册通知冷启动协议或 COM 入口；应用退出后不因旧通知重启。安装版的开始菜单快捷方式提供 AUMID；便携运行不保证系统通知可用。系统禁用通知、勿扰模式和系统投递行为可能影响显示，失败记录在现有日志中。
- 本次使用锁文件原有 `windows 0.62.2` 版本并启用通知所需 API，原许可快照已包含其许可；不升级运行核心或其他依赖版本。
- 单元、隔离和 Windows XML / 回调检查不替代实际通知显示、人工点击及手机出画面；旧版空闲 CPU / 内存测量不直接作为 0.4.0 实测数据。

## 0.4.1 通知修复与 Wi-Fi 总开关（2026-11-05）

- 用户反馈 USB 通知没有反应时，主窗口已经最小化或隐藏到托盘，符合原提醒范围。原生诊断发现首次 `ToastNotifier.Setting` 返回 `0x80070490`（找不到元素）会令旧实现提前退出；补齐应用标识后，该首次查询仍可能返回同一错误，不能把标识缺失认定为唯一根因。
- 仅将上述“尚无权限记录”查询结果按未知处理，继续尝试 `Show`；明确的禁用结果继续拒绝，其他权限查询错误、准备或发送失败仍反馈日志。未知不等于用户已经允许通知，实际显示仍由 Windows 决定。
- 使用 `com.qzz.mirror` 作为当前进程通知标识，运行时只补齐当前用户应用标识下缺失的显示名称和图标元数据。图标缓存在应用本地目录；保留已有注册值，不更改 Windows 通知开关或勿扰设置。便携测试入口也执行该初始化，无需仅依赖安装快捷方式；不注册 COM、协议或退出后的通知冷启动。
- Wi-Fi 总开关位于主页面侧栏底部，设置字段为 `wifiEnabled`，旧配置缺失时默认为 `true`。保存该开关时保留帧率、置顶、连接偏好等其他设置。
- 关闭时隐藏仅无线的设备、同设备的 Wi-Fi 通道标签与保存地址，并禁止手动连接、USB 辅助无线配置、配对、无线启动和自动恢复；重新开启后保留的地址可以再次使用，不自动开始投屏。
- 用户确认关闭开关时同时停止当前 Wi-Fi 投屏。后端也阻止仍在启动或恢复的自有 Wi-Fi 会话继续创建子进程；USB 会话不被停止或改投。没有 Wi-Fi 可用时，“自动”只在所选设备内考虑 USB。
- 开关不关闭设备 Wi-Fi、不清空保存地址、不执行全局 `adb disconnect` 或 `kill-server`，不干预其他程序的连接和投屏。
- 0.4.1 首先只编译用于用户验证的 Windows x64 测试程序，当时未运行安装包、ZIP 或 GitHub 发布流程；既有 0.4.0 本地产物保留。后续发布范围按下方新增决策执行。
- 隔离原生通知发送和激活测试与真正的设备检测、通知按钮、手机出画面分别记录；未重新测量的 0.4.1 空闲资源占用仍为待验证。
